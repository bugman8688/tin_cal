# ADR-0003：节假日四级降级链路

- 状态：已采纳
- 日期：2026-11-26

## 背景（Context）

大陆放假 / 补班安排每年由国务院办公厅发布，没有官方 API。可用的第三方数据源都是社区维护的静态 JSON，任何一个都可能出现访问慢、被墙、仓库改名或数据缺失。

月历的休 / 班角标属于「锦上添花」信息：没有数据时不画即可，但**不能因为拉取失败就整月都变成无标记**——用户会误以为当月没有假期。

## 决策（Decision）

采用四级降级链路，任何一级成功即停止，全部失败也必须保留可用数据：

| 顺序 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 主源（用户可选） | `github` / `jsdelivr` / `npmmirror` 之一，默认 `github` |
| 2 | 其余两个源 | 按 `HolidaySource.allCases` 顺序依次尝试 |
| 3 | 本地缓存 | 上次成功结果写入 `Caches`，含 `sourceID` 与 `updatedAt` |
| 4 | 内置快照 | 打进 App 包里的 `holiday_snapshot.json`，作为最终兜底 |

配套规则：

- **初始化先加载内置快照**，保证界面从第一帧就有数据，网络请求在后台进行。
- 每个源都要求「解析结果非空」，空数据视为失败并继续降级。
- 网络层 10s 请求超时、20s 资源超时；超时、HTTP 错误、JSON 解析失败分开上报，设置页展示具体原因。
- `HolidayStore.officialYears` 维护「已官方发布」的年份集合，不在集合内的年份一律不画休 / 班角标，只按周末判断。
- `npmmirror` 是**全量**数据（忽略年份参数），另外两个源按年取文件；`workdays` 表示补班（周末上班），`inLieuDays` 表示调休放假，解析时不能混为一谈。

## 备选方案（Alternatives）

1. **只用一个源**
   - 放弃原因：单点故障，源一旦不可用就长期无标记。
2. **失败即返回空**
   - 放弃原因：月历整月失去休 / 班标记，且用户无法区分「真没假期」和「拉取失败」。
3. **内置多年数据不联网**
   - 放弃原因：假期安排每年才发布一次，内置只能覆盖历史年份，新一年必然缺数据。
4. **抓官方网页解析**
   - 放弃原因：页面结构不稳定，维护成本高于社区 JSON。

## 后果（Consequences）

正面：

- 弱网 / 被墙 / 源挂掉时仍能显示最近一次成功的数据或内置快照。
- 设置页能看到当前实际来源、更新时间与失败原因，问题可定位。
- 每年只需更新内置快照与 `officialYears`，其余自动按年拉取。

代价与边界：

- 内置快照有滞后性，新年份数据发布前只能靠联网刷新。
- 缓存与内置快照都可能与最新安排不一致，界面上不保证「一定正确」，只保证「一定有数据」。
- 新增数据源时必须同时补 `HolidaySource` 的 URL、解析分支与探测逻辑，并确认它是按年还是全量。
- 未发布年份不画角标是刻意为之：宁可少标，不可错标。
